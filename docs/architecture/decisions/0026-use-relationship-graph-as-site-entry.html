ADR 0026: Use the Ontology Relationship Graph as the site entry

Status

Accepted. Supersedes the separate /graph/ entry path in ADR 0025.

Context

The site landing page lists references and graph links for the same vocabularies. The Ontology Relationship Graph already offers all four vocabularies and the SQL API example through its dataset selector. A separate landing page duplicates that navigation and makes the available views harder to discover.

Decision

  • Render the Ontology Relationship Graph directly at the site root, with one selector naming all five datasets and the existing fixed-layout interactions.
  • Link German and English references and the authoritative Turtle source for the selected dataset. Keep example specifications and the source repository available from the same interface.
  • Build the viewer HTML and self-hosted Cytoscape.js asset at the site root. Internal graph links point to ?ontology=<key> relative to that root, so the same artifact works under the GitHub Pages repository prefix and localhost.
  • Preserve /graph/ and /graph/index.html links with a static client-side redirect to the root, carrying query parameters and fragments unchanged.
  • Keep vocabulary namespace pages, WIDOCO references, RDF downloads, example resources, and legacy WebVOWL URLs at their existing locations.

Consequences

Readers can select any available graph and open its references from one entry point. The separate card-based landing page is removed. Static publication, ontology boundaries, dataset extraction, and product compilation are unchanged. The compatibility redirect requires JavaScript; a plain root link remains as its fallback. No additional library or runtime service is introduced.

Alternatives considered

  • Keep the card-based landing page and reduce its links. This would still duplicate the viewer's dataset selection.
  • Redirect the root to /graph/. This preserves two entry paths and leaves the actual site root as an intermediate page.
