ADR 0027: HTML-Dokumentation und Diagrammmodelle vereinheitlichen

Status

Accepted. Löst ADR 0026 ausschließlich bezüglich des Root-Einstiegs ab. Die festen Ontologiegraphen aus ADR 0025 bleiben bestehen. Entscheidung nach bestätigtem Dokumentationsinterview.

Kontext

Markdown-Dokumente, C4-/arc42-Diagramme, eigenständige Archify-Seiten und Ontologiereferenzen hatten unterschiedliche Einstiege. Der Graph bündelt die Vokabulare gut, erklärt aber nicht allein Architektur, Arbeitsabläufe und Entwicklung. Redaktionelle Änderungen sollen vor einem Deployment lokal sichtbar sein.

Entscheidung

  • Kanonische redaktionelle Quellen sind HTML unter docs/, einschließlich Kontext, Glossar, Produktbeschreibungen und ADRs. Kurze README-Dateien und AGENTS.md bleiben Markdown-Einstiege; generierte Issue-Texte bleiben Vertragsausgaben, keine redaktionellen Dokumente.
  • Die statische Website bietet Überblick, Architektur, Abläufe, Entscheidungen, Ontologien und Entwicklung mit gemeinsamer Navigation, Suche und Hell-/Dunkel-Theme. arc42 bleibt das zwölfteilige Gerüst; C4 liefert darin Strukturansichten.
  • Archify-Modelle unter docs/diagrams/*.json sind die einzige redaktionelle Diagrammquelle. Ein lokal gepinnter Renderer unter tools/vendor/archify/ liefert validierte HTML-Artefakte. Der deutsche Katalog und eine Same-Origin-Theme-Bridge sind dokumentierte lokale Anpassungen. Es gibt keine parallel gepflegten Mermaid-Diagramme.
  • Der Ontology Relationship Graph lebt unter /ontologies/ und bietet weiter vier Vokabulare plus SQL API Example. Namespace-, RDF- und Referenzpfade bleiben stabil. /graph/ und alte Root-Links mit ?ontology= leiten mit Query und Fragment weiter.
  • Documentation Site Builder komponiert die Quellen. Documentation Preview Server beobachtet sie lokal, baut nach gespeicherten Änderungen und behält bei Fehlern den letzten gültigen Build. Quick Builds erneuern Graphdaten, nicht WIDOCO-Referenzen; ein vollständiger Build erneuert beides. Speichern löst keinen Push aus.
  • Historische ADR-Bedeutung, Status und englische Originaltexte bleiben erhalten; neue Beschlüsse supersedieren sie ausdrücklich. Die Migration verändert keine Produktprotokolle oder RDF-Semantik.

Konsequenzen

HTML-Quellen werden direkt bearbeitet; der Build benötigt keinen Markdown-Renderer. Lokale Vorschau und GitHub Pages benutzen dieselbe Komposition. Suchindex, Links, Prefix-Verträglichkeit und Diagramme werden geprüft. Node ist eine neue Dokumentations-Toolchain-Abhängigkeit, keine Produktanforderung. Gepinnte Archify-Dateien, Lizenzen und lokale Anpassungen müssen bei Updates gemeinsam geprüft werden. HTML, Suchindex und Archify-Artefakte sollen bei unveränderten Quellen byte-identisch sein; WIDOCO bleibt davon ausgenommen.

Alternativen

  • Markdown als Quelle und HTML als Build-Ausgabe: verworfen, weil ausdrücklich direkte HTML-Bearbeitung gewünscht ist.
  • Graph als gesamter Root-Einstieg behalten: deckt Architektur und Entwicklung nicht ausreichend ab.
  • Archify, C4 und Mermaid unabhängig pflegen: schafft konkurrierende Wahrheiten.
  • Bei jeder lokalen Änderung WIDOCO neu erzeugen: verlängert den Preview-Zyklus unnötig.
