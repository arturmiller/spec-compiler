Kanonische Fachsprache

Englische Fachbegriffe und Elementnamen bleiben in Code, Specs und Architektur stabil. Die Referenz definiert ihre Bedeutung und zu vermeidende Aliase; die deutsche Bedienoberfläche führt keine konkurrierenden Namen ein.

Relationships

  • One Rule Set has one or more Rule Set Versions; a Decision uses exactly one version selected from authored half-open Validity Periods by its explicit Decision Date.
  • A Decision Product receives a Decision Request and emits one Decision Result through Decision Protocol v1 while implementing the referenced Decision Contract.
  • One Rule Set Version contains one or more Rules and has one Validity Period.
  • A Rule references one or more Conditions and exactly identifies its conclusion or Obligation.
  • Under Obligation Evaluation Conventions v1, a Rule Condition Evaluation maps satisfied to a fulfilled Obligation Evaluation, violated to violated, and unknown to unknown.
  • A Condition has exactly one Condition Evaluation within a Decision.
  • An unknown Condition Evaluation identifies at least one Fact Gap.
  • One Fact Question elicits the Fact for exactly one Condition. An undetermined Decision Result selects at most one Next Question from its current Fact Gaps by the explicit priority convention.
  • A client answers a Next Question by adding the Fact to the complete Case and submitting another Decision Request; the protocol retains no session state.
  • A Source has one or more Source Revisions; a Source Citation points to exactly one revision.
  • Every derived Decision Outcome, Obligation, and Evidence Requirement has Provenance to a Spec statement or named, versioned convention.
  • An Evidence Requirement has its own Source Citation and applicability Conditions. A satisfied supported Condition does not fulfill it.
  • Under Evidence Evaluation Conventions v1, only matching Evidence with an explicit accepted Evidence Assessment makes an applicable Evidence Requirement Evaluation fulfilled; otherwise it is missing.
  • The Funding Domain Ontology may use the Decision and Obligation Core Ontology. The Cloud Compliance Domain Ontology uses the same core semantics; neither Domain Ontology is part of the SHACL Contract Ontology.

Example dialogue

Developer: "The applicant did not tell us whether they own the building. Is the applicant therefore ineligible?"

Domain expert: "No. Ownership is a required Fact, so its absence is a Fact Gap and the ownership Condition Evaluation is unknown."

Developer: "Then does the Decision Outcome become unknown?"

Domain expert: "Only if that gap prevents a unique outcome. A separate, satisfied exclusion Rule could already entail ineligible."

Developer: "Which question should we ask next?"

Domain expert: "Only the Fact Question for a current Fact Gap. Question Selection Conventions v1 choose the lowest authored priority, and a determinate result has no Next Question."

Developer: "And eligible means KfW will approve the application?"

Domain expert: "No. In the KfW 458 Applicant Eligibility Pilot it means only that the modeled applicant-eligibility question is positive under the selected Rule Set Version."

Flagged ambiguities

  • "Unknown Fact" sounds like a third truth value stored as a Fact. Use Fact Gap for missing input and unknown only for a Condition Evaluation or serialized undetermined Decision Outcome.
  • "Eligible" can mean applicant eligibility, measure eligibility, complete application readiness, or an actual funding decision. The pilot uses it only for the explicitly named applicant-eligibility question.
  • "Source" previously meant the immediate origin of a generated requirement. Keep the compiler invariant precise: generated output originates in a Spec statement or convention; an external Source Revision is reached through a Source Citation in that Spec.
  • "Requirement" can mean a Condition, an Obligation, or an Evidence Requirement. Use the specific canonical term.
  • "Decision and Obligation Compiler" can sound like a second software system. The canonical capability is Decision and Obligation Compilation inside the existing Spec Compiler.
  • A document publication date and a Validity Period are not interchangeable; applicability must be declared explicitly.
