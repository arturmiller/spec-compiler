Dokumentation · Architektur · Ontologien

Von expliziten Specs zu überprüfbarem Verhalten.

Der Spec Compiler übersetzt RDF-/SHACL-Spezifikationen in deterministische Verträge, Black-Box-Nachweise und kleine Arbeitsaufträge. Produktentwickler behalten die Wahl ihrer Implementierungstechnologie.

Architektur verstehen

Systemgrenze, Bausteine und Qualitätsziele. arc42 und C4 erschließen dasselbe System mit interaktiven Archify-Ansichten.

Abläufe nachvollziehen

Wie Specs kompiliert, Produkte geprüft und Decision Requests ausgewertet werden.

Begriffe erkunden

Fünf getrennte Beziehungsgraphen: Contract, Decision Core, Funding, Cloud Compliance und das SQL-API-Beispiel.

Entscheidungen verstehen

Die Gründe, Alternativen und Folgen der Architekturentscheidungen bleiben nachvollziehbar.

Am Projekt arbeiten

Einrichtung, Quellen, Referenzprodukte, Build und lokale Vorschau.

Dieselbe Sprache verwenden

Die verbindlichen Begriffe und ihre Beziehungen: Spec, Decision Contract, Fact Gap, Evidence Requirement und mehr.

Ein System, klare Grenzen

Der Spec Compiler umfasst Kompilierung, Contract Verification Harness und Dokumentationsbuild. Ein Generated Product läuft separat und wird ausschließlich über sein deklariertes Protokoll beobachtet. GitHub Pages veröffentlicht die statische Dokumentation.

Drei fachliche Referenzprodukte

SQL API

Ein Artikelvertrag verbindet HTTP-Antwort, OpenAPI und explizite SQLite-Speicherung.

KfW 458

Eine begrenzte Antragstellerentscheidung prüft Rules, historische Gültigkeit, Fragen und getrennte Nachweise.

Cloud Compliance

Ein zweiter Decision-Schnitt prüft NIST IA-2 und IA-2(1) mit derselben domänenunabhängigen Semantik.
Keine erfundenen Anforderungen. Jeder generierte Nachweis stammt aus einer expliziten Spec-Aussage oder einer benannten, versionierten Konvention. Generierungsprinzipien lesen.
