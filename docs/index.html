Spec Compiler

Wie aus einer Spezifikation ein überprüfbarer Vertrag wird.

Der Compiler liest ausdrücklich beschriebene Anforderungen und erzeugt daraus Vertragsdateien, Tests und Arbeitsaufträge. Ein getrenntes Prüfwerkzeug kontrolliert anschließend das Verhalten des Produkts – ohne dessen Implementierung zu importieren.

Compiler verstehen

Vom Einlesen über die Validierung und das interne Modell bis zu Ausgaben und Produktprüfung. Hier beginnt der Erklärungspfad.

Selbst ausprobieren

Ein ausführbares SQL-Einstiegstutorial und zwei darauf aufbauende Decision-Tutorials zeigen die Wirkung einer Spec-Änderung.

Details nachschlagen

Profile, Protokolle, Konventionen, Architektur und das zentrale Glossar – getrennt vom Einstieg.

Compiler und Produkt sind getrennt

Autorinnen und Autoren legen die Anforderungen fest. Der Spec Compiler übersetzt sie in deterministische Vorgaben. Menschen oder optionale Coding Agents implementieren das Produkt; Tests beobachten ausschließlich seine vereinbarte Schnittstelle.

Keine erfundenen Anforderungen. Eine generierte Verpflichtung muss auf eine ausdrückliche Spec-Aussage oder eine benannte, versionierte Konvention zurückgehen. Fehlende Angaben sind Fehler, keine Einladung zum Raten. Verbindliche Regeln lesen.

RDF-Begriffe lassen sich im Ontologiebereich erkunden. Wer das Projekt entwickelt oder die Website pflegt, findet die entsprechenden Anleitungen unter Mitwirken.
