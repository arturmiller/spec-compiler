Tutorial 3 · denselben Decision-Kern wiederverwenden

Fachdomäne wechseln, Semantik beibehalten.

Dieses Beispiel verwendet dieselben Decision-, Quellen-, Frage- und Evidence-Konzepte wie das KfW-Tutorial. Die fachlichen Cloud-Typen und Ergebnisse liegen in einem eigenen Vokabular.

Das Beispiel deckt nur die kuratierten Aussagen zu NIST SP 800-53 Rev. 5 IA-2 und IA-2(1) anhand gelieferter boolescher Fakten ab. Es ist kein vollständiges Assessment, keine Zertifizierung, kein Provider-Konfigurationsscan, keine Remediation und keine Sicherheitsgarantie.

1. Eigenes Übungsprodukt anlegen

uv run --extra dev python tools/tutorial_workspace.py cloud
uv run --extra dev python tools/generate.py --product products/tutorial_cloud_access_compliance
uv run --extra dev pytest -q products/tutorial_cloud_access_compliance/tests

Erwartung: Die generierten Decision-Nachweise bestehen. Die Testfälle in conformance_cases.ttl decken positive, negative und undeterminierte Ausgänge sowie Pflichten- und Evidence-Status ab.

2. Drei unterschiedliche Bewertungen lesen

Die Decision-Spec benennt Regeln und die verlangten Fakten. Eine Obligation ist eine ausdrücklich auferlegte Pflicht. Ihre Bewertung projiziert den Zustand der zugehörigen Regelbedingung. Eine Evidence Requirement besitzt dagegen eigene Anwendbarkeit und Quellenherkunft.

Für die MFA-Nachweisanforderung müssen passende Evidence-Typen und ausdrückliche Assessments vorliegen. Die Herkunft verweist separat auf die kuratierte Assessment-Quelle. Weder Belegbewertung noch Pflichtenstatus verändern die zugrunde liegende Condition Evaluation oder den Decision Outcome.

3. Ein Fragetext ist ausdrücklich verfasst

Suche im Übungsprodukt in specs/decision_contract.ttl die sdo:questionText-Aussage zur Nutzung von Multi-Faktor-Authentifizierung für privilegierte Konten. Der Compiler formuliert diese Frage nicht aus Labels und wählt ihre Reihenfolge nicht nach Datei- oder RDF-Reihenfolge.

4. Die Frage ändern und ihre Wirkung prüfen

Ersetze nur diesen Text durch Nutzen privilegierte Konten Multi-Faktor-Authentifizierung?. Lasse Condition, Quellenverweis und Priorität unverändert. Regeneriere und prüfe:

uv run --extra dev python tools/generate.py --product products/tutorial_cloud_access_compliance
uv run --extra dev pytest -q products/tutorial_cloud_access_compliance/tests

Erwartung: Die Vertragsdatei enthält den neuen Text. Der generierte Frageablaufnachweis erwartet genau diesen Text; das Referenzprodukt liest die Vertragsdatei und gibt ihn beim entsprechenden aktuellen Fact Gap wieder. Regeln, Pflicht- und Evidence-Semantik bleiben unverändert.

Was das Beispiel zeigt

Eine andere Fachdomäne benötigt keine zweite Compilerimplementierung. Der domänenunabhängige sdo:-Kern bleibt gleich, während Cloud-Fakten und Outcomes cloud: verwenden. Zwei Beispiele allein beweisen aber keine universelle Ontologie. Profilreferenz · Cloud-Vokabular erkunden.
